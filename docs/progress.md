# Прогресс
## ЛАБ 1
- Создан проект React + TypeScript + Vite.
- Настроен стартовый экран Habit Tracker
- Сохранён проект на GitHub

ЛР 2 — Страницы приложения и навигация

Реализована многостраничная навигация SPA на базе react-router (BrowserRouter, Routes, Route, NavLink, Link, Outlet, Navigate) поверх общего layout (frontend/src/app/AppLayout.tsx). Описаны типы сущности и демонстрационный массив привычек (не менее пяти записей), добавлены компонент карточки (HabitCard), страницы списка, подробностей по id (useParams), заглушка создания и страница NotFoundPage для неизвестных маршрутов.

Проверка сценариев (ЛР 2)

-Переход на главную и список: открыть / (редирект на список привычек), убедиться в отображении карточек и навигации, проверить узкий экран (~360 px) и переход по Tab / Enter.

-Карточки и прямое открытие по URL: открыть две разные карточки привычек, затем открыть URL существующей карточки в новой вкладке и обновить страницу — данные отображаются без потери.

-Страница создания и граничные маршруты: перейти на экран создания (заглушка), проверить несуществующий маршрут (/unknown) и несуществующий id карточки — отображаются разные сообщения с возвратом к списку.

-Пустой список и сборка: временно проверить пустой массив записей, вернуть демонстрационные записи, проверить npm run build и npm run preview в frontend.

ЛР 3 — Формы и локальное состояние приложения

Состояние списка привычек поднято в frontend/src/App.tsx с неизменяемыми обновлениями (create, update, delete) и генерацией id через crypto.randomUUID(). Создана переиспользуемая форма с изолированным черновиком (initialValues, отмена без сохранения), обязательными полями, предметной проверкой и сохранением введённых данных при ошибке валидации. Добавлены экран редактирования, удаление с подтверждением, локальный фильтр со сбросом и явное пояснение о временном хранении данных в памяти до перезагрузки страницы.

Проверка сценариев (ЛР 3)

-Создание и просмотр: создать новую привычку через форму, перейти на её карточку и вернуться к списку — запись присутствует при внутренних переходах.

-Редактирование и отмена: изменить поля и статус существующей привычки и сохранить; затем открыть редактирование, внести изменения и нажать «Отмена» — несохранённые правки не применяются.

-Валидация и сохранение черновика: отправить форму с пустым/пробельным названием, отсутствующим обязательным полем или нарушением предметного правила — появляется сообщение об ошибке, введённые значения остаются в форме.

-Фильтр, удаление и сброс при обновлении: переключить локальный фильтр и сбросить его; отменить удаление, затем подтвердить и проверить переход по адресу удалённой записи; удалить все записи, создать новую из пустого состояния и обновить страницу — возвращается исходный демонстрационный набор.

## ЛР 4 — Загрузка справочника по HTTP

Реализована загрузка справочника тегов из `${import.meta.env.BASE_URL}demo/tags.json` через `frontend/src/services/tags.ts` (`getTags`, `parseTags`) и хук `frontend/src/hooks/useTags.ts` (`useTags`) с проверкой `response.ok`, рантайм-валидацией элементов и уникальности `id`, отменой запросов через `AbortController` при размонтировании или перезапуске, а также сохранением черновика формы при ошибках и повторных попытках.

### Проверка сценариев

1. **Загрузка (`loading`)**:
   - Откройте страницу с формой и в DevTools на вкладке *Network* включите замедление сети (например, *Slow 3G*) или искусственно задержите ответ для `demo/tags.json`.
   - Убедитесь, что до завершения запроса отображается состояние загрузки (`status === 'loading'`), а после получения валидных данных подгружаются теги (`status === 'success'`).

2. **Ошибка (`error`)**:
   - В DevTools на вкладке *Network* переключите сеть в режим *Offline* либо временно укажите несуществующий файл в `frontend/src/services/tags.ts` (например, `demo/tags-missing.json`).
   - Убедитесь, что запрос завершается ошибкой (`!response.ok` или сетевой `TypeError`), хук переходит в состояние `error`, а интерфейс показывает сообщение об ошибке и кнопку повтора.

3. **Пустой ответ (`[]`)**:
   - В `frontend/public/demo/tags.json` временно запишите пустой массив `[]` и обновите страницу.
   - Убедитесь, что `parseTags` пропускает пустой массив без ошибки, статус переходит в `success` с пустым массивом данных, и интерфейс работает штатно.

4. **Неверная структура ответа**:
   - В `frontend/public/demo/tags.json` временно подставьте невалидные данные: не массив (например, `{}`), объект без `id` или `name`, пустые строки/пробелы или повторяющиеся `id`.
   - Убедитесь, что `parseTags` выбрасывает ошибку, хук переводит состояние в `error`, и интерфейс отображает ошибку вместо некорректных данных.

5. **Повторная попытка без потери черновика (`retry`)**:
   - Заполните поля формы черновика.
   - Вызовите ошибку загрузки справочника (например, включив *Offline* или временно подменив путь), затем верните доступность корректного `frontend/public/demo/tags.json` и нажмите кнопку повтора (`retry`).
   - Убедитесь, что справочник перезагружается заново, а все введённые в форму поля остаются нетронутыми.
